# API Contracts: @repo/jest-config

## Overview

`@repo/jest-config` is a **configuration-only shared library** that provides a standardized Jest configuration object for all backend services in the ticketing monorepo. It contains no HTTP endpoints, database schemas, or runtime code.

---

## Part A: HTTP API Endpoints

**None.** This package is a Jest configuration library and does not expose any HTTP endpoints.

---

## Part B: Database Schema

**None.** This package does not interact with any database.

#### Full Definition

```javascript
// packages/jest-config/jest.config.js (lines 1-7)
module.exports = {
  preset: 'ts-jest',
  testEnvironment: 'node',
  verbose: true,
  modulePaths: ['<rootDir>/src'],
  watchPathIgnorePatterns: ['globalConfig'],
};
```

#### Configuration Properties

| Property | Type | Value | Purpose |
|----------|------|-------|---------|
| `preset` | `string` | `'ts-jest'` | Uses ts-jest preset for TypeScript transpilation during test execution |
| `testEnvironment` | `string` | `'node'` | Tests run in Node.js environment (not jsdom/browser) |
| `verbose` | `boolean` | `true` | Displays individual test results with suite hierarchy |
| `modulePaths` | `string[]` | `['<rootDir>/src']` | Enables absolute imports from the `src` directory in test files |
| `watchPathIgnorePatterns` | `string[]` | `['globalConfig']` | Prevents Jest watch mode from rerunning tests when `globalConfig` files change (typically generated by mongodb-memory-server) |

#### Consumer Usage Pattern

Each consuming service follows this identical pattern (`services/auth/jest.config.js`, lines 1-6):

```javascript
const baseConfig = require('@repo/jest-config');

module.exports = {
  ...baseConfig,
  setupFilesAfterEnv: ['./src/test/setup.ts'],
};
```

The consumers:
1. Import the full configuration object as `baseConfig`
2. Spread all properties into a new object
3. Add service-specific `setupFilesAfterEnv` pointing to a local test setup file
